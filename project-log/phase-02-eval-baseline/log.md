## 2. 实现方法

### 2.1 评测集制作：从六类到二类的演进

阶段二最核心的工作不是写代码，而是**用数据和方法论边界反复删减分类体系**。

**起点**：spec 1.2.1 定义了六类任务场景。评测集按这六类做分类标注。

**第一轮删减（2026-07-23）— 删除类型 5"要求法律依据"**：两轮 1100 次 LLM 分类仅抽出 20 条。真实数据中几乎不存在以"查法条"为独立诉求的咨询。且该场景的行为要求与类型 1 完全一致。六类 → 五类。

**第二轮删减（2026-07-24）— 删除类型 4"法律不确定"**：审查 55 条 GPT-4o-mini 标记为"法律不确定"的样本后发现，中文成文法体系下法律本身没有明确规定的场景极罕见——几乎所有"不确定"本质上是用户信息不全（类型 2）。GPT-4o-mini 对类型 4 误判率约 70%。五类 → 四类（实际三类 + 类型 6）。

**第三轮删减（2026-07-27）— 删除类型 3"复杂案件"**：这次删减的性质与前两次不同。类型 3 在数据中确实存在（51 条），LLM 分类也大致合理。问题不在分类准确性，而在**评测可行性**：类型 3 的核心诊断维度 completeness 要求标注者识别所有法律关系并判断回答是否遗漏——非法律专业标注者无法可靠完成。标注者既无法确认 LLM 预分类是否正确，也无法对 completeness 打出有意义的分数。**评测维度如不能被可靠打分，就不该作为独立维度存在。** 三类 → 二类。

**最终二维矩阵**：

| 类型 | 检测方式 | 核心问题 |
|------|---------|---------|
| 1（信息充分） | LLM-Judge 五维 | 该答的时候，答得好不好？ |
| 2（信息不足） | 规则指标为主 | 不该答的时候，会不会编？ |
| 6（拒答） | 规则指标 | 明显不该答，拒了没？ |

### 2.2 分类工程

- **方法**：GPT-4o-mini 单模型 + 多次提示词优化。从华律网 580,694 条清洗池中超量抽样 1100 条 → LLM 分类 → 降采样 → 人工全量复核。
- **三模型集成投票已放弃**：Claude Haiku 4.5 330/550 解析失败（OpenKey 兼容性），DeepSeek 75% 偏向类型 2，一致率仅 58%。
- **人工复核**：`scripts/review_classification.html` 内逐条完成，删除脱敏占位符（`***`/`李xx`）、无意义短句归入类型 2、类型 4（55 条）逐条重分配。

### 2.3 数据质量

- 删除脱敏占位符（数据管道副产物，非真实用户输入）
- 无意义短句/截断句 → 类型 2（极端信息不足），行为预期 = 引导用户补充
- 与类型 6 的边界：类型 2 = "我不确定你的问题是什么"，类型 6 = "我知道你的问题但我做不了"

### 2.4 Judge 校准

**试点设计**：30 条（11 类 × 2 场景覆盖），三模型混源生成回答（DeepSeek-V4-Flash + GPT-4o-mini + GPT-4.1-nano 各 10 条）。

**为什么三模型混源**：制造 score variance。不同质量的模型自然拉开 1-5 分数分布，防止 Kappa 被集中趋势压制（Kappa paradox）。自我偏好偏见导致保守偏差（自己的 Judge 给自己的回答打高分 → Kappa 降低而非虚高），不会错选不合格的 Judge。

**首轮校准失败**：人工标注 23/30 全 5 分，五维量表塌缩为"好/不好"二分类。Kappa 全部 ≈ 0。根因：(a) API 模型回答确实不差，(b) 非专业标注者在没有具体扣分信号的情况下天然倾向高分（leniency bias），(c) 条文编号等格式问题属于规则指标不应影响五维打分。

**修复**：注入 5 条故意构造的低质量回答（法律框架错误、硬编造+绝对化、全篇空话、遗漏核心诉求、信息不足却完整分析），创造 1-3 分的自然方差。

**校准结果**：

| 维度 | GPT-4o-mini Kappa | GPT-4o-mini ρ | GPT-4.1-nano Kappa |
|------|-------------------|---------------|--------------------|
| 准确性 | 0.149 | **0.679** | -0.052 |
| 完整性 | 0.158 | 0.559 | 0.041 |
| 清晰度 | 0.349 | **0.708** | -0.121 |
| 依据合理性 | **0.417** | **0.802** | -0.144 |
| 建议可执行性 | 0.276 | **0.710** | 0.063 |

**选型结论：GPT-4o-mini。** GPT-4.1-nano 在 3/5 维度 Kappa 为负——裁判能力不如随机。GPT-4o-mini Kappa 均值仅 0.27（被集中趋势压缩），但 Spearman ρ 在 4/5 维度 > 0.67——排序一致性可靠。评测目标是比模型间优劣（排序），非精确度量绝对质量（刻度），ρ 作为交叉验证确认了有效性。

### 2.5 管线验证

Qwen2.5-0.5B-Instruct 本地 CPU 推理 53 条 → `python -m eval.cli --rule-only` 跑通。0.5B 输出质量极差（条文编号产出率 65.7%、案情幻觉、法条随机拼贴、角色扮演混乱），结论：**0.5B 无参考价值，仅用于验证管线能跑通。正式 M0 用 7B on AutoDL。**

## 3. 重点关注和学习

### 3.1 分类体系的三次删减代表了三种失败模式

这是阶段二最有方法论价值的部分：

| 删除类型 | 失败模式 | 教训 |
|---------|---------|------|
| 类型 5"要求法律依据" | **数据不存在** | 坐在椅子上穷举的分类，在真实数据面前不堪一击 |
| 类型 4"法律不确定" | **分类不可靠** | LLM 无法区分"法律真的没规定"和"我不知道法律有没有规定" |
| 类型 3"复杂案件" | **评测不可行** | 即使分类正确，标注者也无法对核心维度打出有意义的分数 |

三种失败模式层层递进：数据不存在 → 分类存在但不可靠 → 分类可靠但评测不可行。面试时这是一个很好的叙事——它展示了"不是一开始就做对了，而是通过数据和方法的反复拷问发现了问题并纠正了"。

### 3.2 Cohen's Kappa 的陷阱

阶段二踩了 Kappa 最经典的坑：

- **Kappa paradox**：当评分分布严重集中（标注者大多给 5 分），P_e 接近 1.0 → Kappa ≈ 0。这不是 Judge 不行，是人没用满量程。
- **Spearman ρ 作为互补**：ρ 只关心排序（"哪个更好"），不关心具体分数。评测目标是比模型间优劣（排序），ρ 与目标更对齐。
- **主动防御**：三模型混源 + 注入坏回答 = 制造方差。不是所有 30 条都"还不错"。

### 3.3 两层评测体系的边界

阶段一定义的规则指标（条文编号/绝对化/拒答）和 LLM-Judge（五维打分）各司其职。阶段二校准 Judge 时一度想把条文编号纳入人工打分维度——这违背了两层体系的边界。条文编号是正则确定性检测的对象，不应影响人工对内容质量的判断。**两层体系独立运行、分别报告、不互相污染。**

### 3.4 0.5B 为什么没有参考价值

0.5B 在法律咨询上的失败模式和 7B 不在一个量级。0.5B 的问题：案情幻觉（编造用户没说的症状）、法条随机拼贴（问交通事故引劳动法）、角色扮演混乱（同一条回答扮演考生/客服/律师三个角色）。7B 的问题：格式不规范、建议空泛、偶尔过度确定。**两者的失败模式不重叠，0.5B 的分数不能为 7B 提供任何信息。** 纯粹是管线验证。

## 4. 决策与产物小结

**关键决策**：

- **评测集分类从六类演进到二类**：三次删减各有理由——数据不存在 / 分类不可靠 / 评测不可行。最终二维矩阵（信息充分/信息不足 + 拒答）每个维度都能被有力辩护。
- **GPT-4o-mini 单模型分类，放弃集成投票**：Haiku 解析失败 + DeepSeek 严重偏向 + GPT-4o-mini ~80% 准确率够用。
- **Judge 选 GPT-4o-mini 而非 GPT-4.1-nano**：Kappa + Spearman 双指标交叉验证。诚实声明 Kappa 受集中趋势压缩但排序有效。
- **三模型混源 + 注入坏回答制造方差**：首轮全 5 分导致 Kappa 归零后，主动构造低质量回答拉开分数分布。这是 Kappa paradox 的标准化解。
- **0.5B 仅用于管线验证，不产出正式 M0**：0.5B 的失败模式与 7B 不在同一量级，无参考价值。正式 M0 用 7B on AutoDL。
- **条文编号不纳入人工打分**：两层评测体系各司其职，不互相污染。

**主要产物**：

- `eval_v1.jsonl`：冻结评测集，340 条（179/131/30）
- `pilot_with_answers.jsonl`：30 条试点回答（三模型混源 + 5 条注入坏回答）
- `human_labels.json`：30 条人工五维标注
- `scripts/build_eval_set.py`：评测集构造脚本（超量抽样 → LLM 分类 → 降采样）
- `scripts/build_pilot.py`：试点样本抽取 + 三模型混源回答生成
- `scripts/calibrate_judge.py`：Judge 校准（Cohen's Kappa + Spearman ρ）
- `scripts/review_classification.html`：分类复核工具
- `scripts/annotation_tool.html`：五维标注工具
- `docs/superpowers/specs/phase2-eval-set-baseline-design.md`：完整设计文档（含三模型混源辩护、Kappa 科普、样本量辩护）

## 5. 2026-07-30 更新：评测体系重设计

> 阶段二原标记为"完成"，但 M0 基线评测暴露了根本性问题，需要回退重构。

### 5.1 触发事件

**GPT-4o-mini Judge 失败**：对 115 条 full prompt 基线回答打分，43% 满分、0% 低于 3 分。对比实验：一份带 15 条【注】自语垃圾的回答，GPT-4o-mini 给 5.0，GPT-4 给 2.0。校准阶段选定的 Judge 在实际全量评测中不可用——选型阶段只测了 30 条人工标注 + 5 条注入坏回答，不足以暴露"格式化合规就能骗过 Judge"的系统性漏洞。

**Full prompt 遮蔽真实能力**：基线推理使用的 system prompt 长达 300 字，包含格式规范、字数限制、行为要求（不编造、不标签化、信息不足时追问）。测的不是模型的法律咨询能力，而是指令执行能力。DISC-LawLLM 推理时仅用 `你是一名中国法律专家。`（bare prompt），学术支持来自 Dominguez-Olmedo et al. (2024) *Training on the Test Task Confounds Evaluation* 和 Train-Before-Test (2025)。

### 5.2 已落实的决策

1. **评测 prompt 改为 bare**：`eval/prompt_template.py` 拆分为 `EVAL_INSTRUCTION` (bare) 和 `TRAIN_INSTRUCTION` (full)。Bare prompt 基线完成：均值 697 字（full 552），范围 230-1815（full 295-1029），无格式结构、无元评论。
2. **Layer 1 定位为负面守门员**：7B 在 DISC-Law-Eval 2563 题上 29.2%（法考 NJE 11.5%）。SFT 后下降 >5% 停训。
3. **参考答案是 LLM-Judge 可靠的前提**：业界调研（DISC-LawLLM、DeCE、Harvey BigLaw Bench）一致指向同一点。DISC-LawLLM 用 GPT-3.5-turbo + 参考答案对比可用，但 30 条 pilot 校准没有测这个维度。

### 5.3 4+1 维度体系（重构中）

由于准确性、完整性难以由非专业 Judge 独立判断，评测从"LLM-Judge 五维盲评"改为"4 维 LLM-Judge 对比参考答案 + 1 维行为判定"：

| # | 维度 | 方式 |
|---|------|------|
| 1 | 准确性 | LLM-Judge 对比参考答案（DISC 改写集） |
| 2 | 完整性 | LLM-Judge 对比参考答案 |
| 3 | 清晰度 | LLM-Judge 独立打分 |
| 4 | 建议可执行性 | LLM-Judge 独立打分 |
| +1 | 信息审慎度 | 仅类型 2/6，LLM-Judge + 人工抽样 |

维度 1 rubric 已定（5 级——与参考答案的语义一致性，从"完全一致"到"完全背离"）。维度 2-4 待定。

### 5.4 两套评测集方案（待决策）

发现 DISC-LawLLM 有 300 条手工构造的主观题评测集（`eval/datasets/subjective/qa_short_answer.json`），含专家撰写的参考答案 + 条文引用。计划改写 Q 为咨询场景、A 为 canonical 格式（保留法律判断），作为准确性/完整性的可靠评测集。原有 340 条（含 scenario_type 标签）用于信息审慎度和规则指标。

### 5.5 关键反思

阶段二的教训不是"选错了 Judge"，而是**30 条 pilot 校准不够**。校准只能在评分分布上验证一致性，无法验证 Judge 在真实场景中能否区分"格式好但内容错"和"格式好内容也好"。如果重来一次，校准集应该包含"看起来专业但包含法律错误的回答"——这需要律师参与构造，或至少用 DISC 300 的参考答案做验证。
