## 2. 实验历程总览

SFT 阶段共跑了 4 轮训练，但**只有 2 轮是设计的消融实验，另外 2 轮是 Bug 修复后重跑**。

### 2.1 实验性质分类

| 轮次 | 变更 | 性质 | 说明 |
|------|------|:---:|------|
| V1 | 半量 baseline | 🔧 **Bug 版本** | 卡 2 仅 4 条、R2 要求编号、R7 存在——三个问题叠加，结果不可用 |
| **V2** | 卡 2 修复 + R2 修复 + R7 删除 | ✅ **真·Baseline** | 三个 Bug 同时修，是有效的 SFT 起点 |
| **V3** | bare instruction | 🔬 **消融变量 #1** | 验证训评 prompt 一致性假设——完整 prompt → `你是一名中国法律专家。` |
| **V4** | 全量数据 | 🔬 **消融变量 #2** | 验证数据规模效应——3,600 → 7,208 条 |

### 2.2 为什么 V1 有三个 Bug 叠加

三个 Bug 并非刻意引入的变量，而是 Phase 3 数据构造和 Phase 2 评测设计的历史遗留：

- **卡 2 Bug**：`build_sft_raw.py` 默认运行顺序为 `[3, 4, 1]`，从未执行卡 2 生成逻辑。该代码从 Phase 3 开始就存在，到第一次 SFT 评测时才发现——卡 2 只有 4 条、审慎度从 0.94 跌到 0.84。
- **R2 冲突**：训练要求"不写条文编号"（防幻觉），评测 R2 却以编号为满分标准。这是 Phase 2 评测体系设计时未考虑训练目标的遗留问题。
- **R7 冗余**：R7（补充额外要点）鼓励模型补充参考未覆盖的内容，与训练目标"简洁高效"冲突。

**关键认知**：V1→V2 不是"消融实验"，是"修 Bug"。把 Bug 修复和变量消融混在同一个实验矩阵里，会导致无法归因——审慎度从 0.84 回到 0.94，到底是卡 2 修好了还是 bare instruction 的作用？答案是卡 2 修好了；bare instruction 对审慎度几乎没有贡献（V3=0.95，V4=0.93）。

## 3. 关键发现与修复

### 3.1 R2 评测与训练目标冲突

训练要求禁止具体条文编号（防幻觉），但评测 R2 以专家参考答案的编号为准。**模型学会了禁止编号，评测却因此扣分。** 决策：修改 R2 判定标准（`judge_checklist.py`），只比对法律名称，不要求编号一致。

### 3.1b R7 删除

R7（"是否补充了参考答案未提及但相关的要点"）存在三个问题：(1) 参考是 ONE correct answer，不补充不等于错；(2) 与训练目标"简洁高效"冲突；(3) Judge 无法区分为"有用的补充"和"无关冗余"。M1 的 R7 下降（84%→71%）不是退步，是模型变简洁了。**决策：删除 R7**。Checklist 从 7 项减为 6 项（R1-R6，准确性 4 项 + 完整性 2 项）。R5-R6 间不存在 trade-off（15 条同时改善，0 条相反）。

### 3.2 卡 2 数据 Bug

半量训练后审慎度下降，排查发现卡 2（信息不足）只有 4 条数据。根因：`build_sft_raw.py` 默认运行顺序 `[3, 4, 1]` 不包含卡 2，且 `len(question) ≤ 30` 的筛选从未在已生成数据上触发。1,541 条短问题（35%）本应有一部分标为卡 2。

修复：从 4,404 条卡 1 中筛选 700 条短问题重新标注为卡 2（剩余 3,701 条为卡 1）。

**数据验证**：700 条卡 2 中 98% 含条件表述、32% 含追问句式、1% 两者皆无。

**预防措施**：
- `validate_raw.py` 新增 `check_card2_quality`：检查卡 2 回答是否含追问/条件表述
- `validate_raw.py` 新增各卡预期数量范围检查：卡 1 (3500-3800)、卡 2 (600-800)、卡 3 (2500-2800)、卡 4 (300-400)、卡 5 (50-100)、卡 6 (400-600)

## 7. 关键技术决策总结

1. **评测与训练同 prompt**：评测用 bare，训练也应用 bare。DISC-LawLLM 的做法是正确的
2. **卡 2 数据量不是问题关键**：卡 2 从 4→700 后审慎度仍不改善，问题在 instruction 而非数据量
3. **R2 评测标准应与训练目标对齐**：训练禁止编号 → 评测不应以编号为满分标准
4. **R7 删除**：鼓励模型简洁是优点，不应被评测惩罚
5. **CLI 统一评测入口**：`eval/cli.py` 重写为 v2，一条命令跑全量评测
6. **SFT 对准确性/完整性/质量有效，对审慎度/拒答无效**：需要 DPO
7. **Loss 曲线验证泛化趋势**：V3 bare instruction 虽然 train loss 更高，但 eval loss 最低 → 更好的泛化能力

## 8. 讨论：如何判断 SFT 已到天花板，应该进入 RL/DPO

### 8.1 为什么这个问题值得讨论

SFT→RL 的切换时机是面试中的高频问题，也是实际项目中容易踩的坑。**切早了**，RL 缺乏稳固基础，reward 信号稀疏，容易训练崩溃；**切晚了**，在 SFT 上投入过多算力，边际收益为零甚至为负。本节结合本项目四轮 SFT 的实际数据，对照业界研究，给出可操作的判断框架。

### 8.2 理论框架：Plasticity-Ceiling（ACL 2026）

RETU 论文（LINs-lab/RETU, arXiv:2512.11470, ACL 2026 Main）提出了后训练的可塑性上限框架，将最终性能天花板 **A_post** 分解为两项：

> **A_post = P_sft + P_L_rl**
>
> - **P_sft**：SFT 打下的基础能力（由专家轨迹质量决定）
> - **P_L_rl**：RL 阶段的可塑性空间（由 SFT 停止时机决定）

关键发现：
- **最小 SFT 验证损失** 与最终后训练上限呈 **r = -0.90 的强负相关**（Llama3.2-3B 上达 r = -0.98）
- **最优切换时机**：SFT 验证损失进入 **稳定期（Stable Regime）或轻度过拟合期（Early Mild Over-Fit Regime）**
- 过早切换（Adaptive Sub-phase）→ RL 无法发挥潜力，甚至反噬性能
- 过晚切换（Severe Over-Fit）→ RL 可塑性被消耗，天花板下降

一句话：**SFT 验证损失不再下降的那一刻，就是进入 RL 的最佳窗口。**

### 8.3 实践警告：SFT 高分 ≠ RL 好起点（ICLR 2026）

另一项研究（"Quagmires in SFT-RL Post-Training", ICLR 2026）在 100+ 模型、100 万 GPU 小时的实验中发现了一个反直觉的事实：

> **Post-SFT 准确率预测 Post-RL 结果的 R² = 仅 0.43**。即 SFT 阶段得分最高的 checkpoint，不一定是进入 RL 的最佳起点。

该研究提出的改进信号：

| 信号 | 含义 | 可靠性 |
|------|------|:---:|
| 验证集泛化损失 | 检测过拟合——val loss 反弹说明 SFT 训练过头了 | 高（用于排除） |
| Pass@large k | 模型"偶尔能答对"的上限——反映 RL 可挖掘的潜力 | 高（用于排序） |
| Post-SFT 准确率 | 直接指标 | 低（R²=0.43，容易误导） |

**Pass@k 和 Pass@1 的差距** 本身就是信号：差距大 → 模型有隐藏能力，RL 可以通过探索释放；差距小 → 模型已经稳定，RL 收益有限。

### 8.4 对照本项目的证据链

将上述框架应用到 LegalGPT 四轮 SFT：

**(1) 验证损失信号——明确指示切换窗口**

| 阶段 | Train Loss | Eval Loss | Eval Loss 趋势 |
|------|:---:|:---:|:---|
| V1 半量 (full prompt) | 1.2399 | 1.1752 | baseline |
| V2 卡2修复 (full prompt) | 1.2387 | 1.1794 | 持平（卡2修复对 loss 影响小） |
| V3 半量 (bare inst) | 1.2567 | 1.1647 | ↓ -0.01 |
| V4 全量 (bare inst) | 1.1844 | 1.1366 | ↓ -0.03 |

V3→V4 eval loss 还在下降（1.165→1.137），说明数据量翻倍仍有收益。但需注意：Eval loss 的降幅（-0.03）已经明显小于 V2→V3 的降幅（-0.01，但那是训评对齐的结构性改进）。如果继续追加数据，预计降幅会进一步收窄。

**(2) 行为类指标——SFT 的结构性盲区**

```
审慎度: 0.94 → 0.95 → 0.93 = 横盘
拒答:   0.1  → 0.1  → 0.13 = 横盘
```

V3→V4 数据量翻倍、eval loss 改善，但审慎度和拒答纹丝不动。这是最有力的天花板信号——**SFT 的训练目标（最大化 P(answer|question)）与此类行为需求（在某些 question 上不应给出 answer）存在根本冲突。** SFT 只能让模型模仿训练分布，而训练分布中卡 1（给答案）: 卡 2（追问）: 卡 5（拒答）≈ 3701:700:79，模型学到的策略是"给答案永远是安全的"。

**(3) 质量维度——已经接近评分上限**

```
清晰度: 2.77 → 2.79 (天花板 ~3.0)
建议:   2.75 → 2.73 (天花板 ~3.0)
```

两个维度在 V3 已经接近满分，V4 的波动在 ±0.02 范围内。继续堆 SFT 数据不会让"写得更好"再提升。

**(4) 边际收益分析**

| 改进 | 手段 | 准确性增益 | 代价 |
|------|------|:---:|------|
| V1→V2 | 卡2修复 | +3% | 重新标注 |
| V2→V3 | 训评对齐 | +4.4% | 重训（零成本） |
| V3→V4 | 数据翻倍 | +3.1% | 训练时间翻倍 |

收益递减曲线明显。如果继续翻倍到 14K 数据，预计准确性增益 < 2%，边际成本上升。

### 8.5 面试应对框架

**面试官问："你怎么判断 SFT 做到什么程度就该停了？"**

回答结构（3 层）：

**第一层（理论）：** 引用 Plasticity-Ceiling 框架——SFT 验证损失不再下降时是最佳切换窗口。核心逻辑：SFT 在"稳定期"停止，保留 RL 阶段的参数可塑性。

**第二层（数据）：** 三项具体信号——
1. **验证损失平坦化**：继续加数据/调参，val loss 降幅收窄到可忽略
2. **目标指标横盘或接近上限**：质量分接近 3.0/3.0，准确性提升靠堆数据代价过高
3. **行为类指标零改善**：审慎度/拒答在数据量翻倍后不动，说明这不是 SFT 的优化目标能解决的问题

**第三层（反直觉提醒）：** SFT 表现最好的 checkpoint 不一定是进入 RL 的最佳起点（引用 ICLR 2026 的 R²=0.43 发现）。应该用 Pass@k 评估模型的可挖掘潜力，而非只看 Pass@1。

**面试追问："为什么 RL 能解决 SFT 解决不了的问题？"**

SFT 的优化目标是最大化 P(answer|question)——它鼓励"对任何输入都产生回答"。审慎度/拒答的本质是**在特定输入上抑制回答行为**，这与 SFT 的训练目标相反。DPO/RL 通过偏好信号（chosen vs rejected），直接教模型"这个情况下给出答案是不好的"——这是一种**对比学习信号**，SFT 的 next-token-prediction loss 无法提供。

### 8.6 本项目结论

SFT 四轮证据充分：准确性/质量已接近上限，审慎度/拒答零改善。**SFT 已经到位，进入 Phase 5 DPO 训练。**
